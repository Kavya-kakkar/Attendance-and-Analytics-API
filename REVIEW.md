# REVIEW.md

Comprehensive code review of starter `app/main.py`. Each defect identified in the starter code is documented below with its exact location, structural failure mode, empirical reproduction symptom, and resolution implemented.

## Confirmed Defects and Resolutions

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | **Timezone collision & incorrect grace evaluation**: `punch_in.replace(...)` assumes local/naive timestamps and compares UTC against IST shift. Furthermore, `minutes = int(diff / 60)` followed by `minutes > 10` returns `0` at `09:40:01` (601 seconds) because `601 // 60 = 10` and `10 > 10` is `False`. R2 requires strict inequality after 10:00 (09:40:00 &rarr; 0, 09:40:01 &rarr; 10). | Punch-in at `09:40:01` IST for a `09:30` shift. Starter returns `0` instead of `10`. | Convert instant to IST; check total seconds difference `diff_sec > 600`; compute `int(diff_sec // 60)`. |
| 2 | `compute_work_hours` (lines 40–41) | **Banker's rounding violation**: Uses Python's built-in `round()`, which performs round-half-to-even (banker's rounding). Rule R4 explicitly specifies arithmetic half-up rounding (`ROUND_HALF_UP`). | A duration of `4.545` hours rounds to `4.54` instead of `4.55`. | Used Python `decimal.Decimal` with `ROUND_HALF_UP` quantized to `Decimal('0.01')`. |
| 3 | `compute_overtime` (lines 44–47) | **Threshold omitted & overnight date shift bug**: R3 states overtime is counted only when &ge; 30 minutes (otherwise 0). | 9 | `punch_in` & `list_attendance` (lines 119, 149) | **Internal ID exposure and unformatted datetimes**: Starter injected `doc["id"] = str(res.inserted_id)`. ## What Was Examined and Decided NOT to Be a Defect

1. **Storing calendar dates and shift times as strings (`YYYY-MM-DD`, `HH:MM`)**:
   - *Reason*: `DATA_MODEL.md` explicitly mandates storing calendar dates and shift times as strings in MongoDB. Converting dates to BSON datetime instants would force an artificial time-of-day and timezone offset onto purely calendar concepts.
2. **PyMongo returning naive UTC datetimes by default**:
   - *Reason*: This is standard PyMongo driver behavior. Setting `tz_aware=True` or explicitly converting naive UTC datetimes to timezone-aware UTC objects at the service boundary cleanly satisfies BSON and API requirements.
3. **Absence of surrogate UUID/ObjectId primary keys in HTTP responses**:
   - *Reason*: The business domain uses `emp_code` as the natural human-readable identifier for employees and the composite tuple `(emp_code, date)` for attendance records. The OpenAPI contract explicitly excludes `_id` and internal surrogate IDs from request and response schemas.
4. **Persisting derived values (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`)**:
   - *Reason*: Rather than recomputing metrics dynamically across hundreds of thousands of documents on every read, `DATA_MODEL.md` and `openapi.yaml` explicitly establish that stored derived values are authoritative, enabling fast, index-accelerated aggregation pipelines.
